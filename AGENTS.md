## Project Shape

- This is an npm package that exposes an opencode provider by wrapping the Claude Code CLI (`claude`), not the Anthropic HTTP API directly.
- Package entrypoint is `src/index.ts`; runtime provider behavior lives mostly in `src/claude-code-language-model.ts`, which now holds the `ClaudeCodeLanguageModel` class and little else. Its free-standing pieces moved out verbatim and it re-exports every symbol tests and `src/index.ts` used to import from it, so an old import path still resolves: `src/prompts.ts` (appended system prompt text and `buildAppendedSystemPrompt`), `src/auto-continue.ts` (the continue-or-stop decision), `src/ask-user-question.ts` (`AskUserQuestion` rendering and its deny message), `src/fast-mode.ts` (`reportFastModeState`), `src/call-options.ts` (session affinity, opencode agent, compaction model, `hasNewUserContent`), `src/proxy-results.ts` (reading opencode's answer back out of the next prompt), `src/control-request.ts` (`can_use_tool` allow/deny), `src/spawn-planning.ts` (proxy defs, MCP config, live tool registry, skill-bridge and plan-mode gates, the proxy server), `src/title.ts` and `src/usage.ts`. The two host methods, `doGenerateForHost` and `doStreamForHost`, did not move: their bodies are closures over the turn's own mutable state.
- `src/message-builder.ts` owns AI-SDK prompt to Claude CLI stream-json message conversion, including `/compact` transcript rendering.
- `src/session-manager.ts` owns Claude CLI process reuse, session ids, LRU eviction, and CLI arg construction.
- `src/cli-version.ts` gates optional CLI flags. Do not pass newly-added Claude CLI flags unconditionally.
- `src/claude-session-bun.ts` + `src/claude-session-wrapper.ts` own the experimental interactive transport (PR #10): the interactive `claude` TUI under Bun's native PTY, prompts typed via bracketed paste, output tailed from the session JSONL transcript. Opt-in via `interactive: true` / `CLAUDE_CODE_INTERACTIVE_TRANSPORT=1`; headless `--print` stays the default.
- **One package serves opencode 1.x and 2.x.** The default export carries both `server` (1.x) and `setup` (2.x). `src/v2.ts` is the 2.x entrypoint, `src/opencode-v2-types.ts` a hand-written mirror of the 2.x API slice, `src/v2-client.ts` answers live-state calls in 1.x shapes, `src/host-tools.ts` renames tool calls into 2.x's vocabulary. See `V2.md`.
- Build output is `dist/`, is gitignored, and is rebuilt by CI. Do not commit `dist/`.

- Test suite: `npm test`. The script enumerates test files explicitly: when adding a `test-*.ts` file you MUST add it to `package.json`'s `test` script or it silently never runs.

## Release Workflow

- Never run `npm publish` manually. Tag push triggers `.github/workflows/publish.yml`, which publishes to npm.
- Publishing uses npm **trusted publishing (OIDC)**, not a token (since v0.6.2): `id-token: write`, npm >= 11.5.1, `npm publish --access public` with **no `NODE_AUTH_TOKEN`**. The trusted publisher must match the repo and workflow filename `publish.yml`; the legacy `NPM_TOKEN` secret is unused. If a publish fails on auth, check that config, not a token. (h #g17)
- Release flow: commit code/docs, then `npm version patch` (or minor/major), then `git push origin master --follow-tags`. Prior tag messages are `v0.x.y`, keep that style, and confirm with `gh run list --limit 3`.
- **Verify a publish from the `Publish package` step's own tail (`+ <pkg>@<version>`) and cross-check the version document's `shasum` against its `npm notice shasum:` line. Never judge a release by the package document, `npm view` or an install from the maintainer's Mac**, where Aikido's minimum-package-age filter hides fresh versions. Read Aikido's event log before calling anything a registry fault. A real auth failure fails the step with a 404 on the PUT. (h #g21)
- GitHub Releases lapsed after v0.9.2 and are optional. Write notes for anything security-relevant or behaviour-changing. (h #g22)
- A freshly published version will NOT appear in a local opencode until `rm -rf ~/.cache/opencode/packages/@khalilgharbaoui/opencode-claude-code-plugin@latest` plus a full relaunch; a plain restart never re-resolves `@latest`. (h #g23)
- Do not add a Claude co-author trailer to commits.
- Keep `README.md` updated when adding public options, env vars, required CLI versions, or behavior users can observe.

## High-Signal Runtime Gotchas

### Aborts, deadlines and process lifetime

- **An abort at a proxy tool boundary is usually opencode, not the operator**: 1.18.32 aborts every step ending in tool calls, and `AbortSignal.reason` is identical either way. Only a positive `busy` from `settleSessionRunState` keeps the pending calls; `unknown` releases. `test-process-lifecycle.ts`. (h #g26)
- **A proxy deadline must not count the operator's time on a permission prompt.** Both timers go through `armProxyDeadline` and its `ProxyDeadlineGuard`; `isProxyCallStillServed` keeps a call only when `emitted` **and** the session reads `busy`, rechecking every `PROXY_DEADLINE_RECHECK_MS`. No guard, a throwing guard or `unknown` end it as before. `test-broker.ts`. (h #g27)
- **Abort sends the CLI an `interrupt` control request** (`interruptTurn`), or the turn runs on and bills. `noteTurnStarted` marks in flight at every stdin write asking for work, and the terminal `result` clears it inside the `rl` handler, **never** a permanent `lineEmitter` listener. `test-session-manager.ts`. (h #g59)
- **`idleProcessTimeoutMs` is off unless set** (`resolveIdleProcessTimeoutMs`, so unset and `0` both arm nothing). Unref'd, cancelled by every get/set/detach/spawn/exit, deleting only the same process object; a process found `turnInFlight` is re-armed, never killed. `test-session-manager.ts`. (h #g60)
- **The child's stdin needs its own `error` listener, and `proc.on("error")` is not it**: an `error` on a listener-less stream throws inside **opencode's** process. `spawnClaudeProcess` attaches one, logs at WARN, calls `settleTurn`, and deliberately does not end the turn. `test-session-manager.ts`. (h #g61)
- **LRU eviction must never take a process that is mid-turn**: `evictIfNeeded` walks insertion order for the first with `turnInFlight !== true`, and when all are busy evicts **nothing** and warns. Do not "restore" the one-liner. Cap is **8**. `test-session-manager.ts`. (h #g62)
- **A deleted opencode session releases everything at once, and host exit kills what is left.** The `event` hook acts on `session.deleted` only (`extractDeletedSessionId`); `deleteActiveProcessesForSession` also drops session id, plan-mode questions, ledger and summary, never matching the `"default"` bucket. `test-process-lifecycle.ts`. (h #g63)
- **A child that closes without a `result` is an error, not a `stop`**: emit an `error` part plus `finishReason: "error"` from `describeChildCrash(exitCode, signal, lastStderr)`. `retainStderr` keeps a 2 KB tail, the branch waits `CHILD_EXIT_STATUS_GRACE_MS` for `exit`, and an abort is exempt. `test-respawn.ts`. (h #g64)
- **Reused-process start watchdog**: `armStartWatchdog()` fires only on the fresh-turn write path, which the inactivity watchdog ignores. First fire (`CLAUDE_CODE_START_WATCHDOG_MS`, 90 s) calls `respawnActiveProcess`, reusing the proxy server, prompt file and mcp hash and appending `--resume`. `test-respawn.ts`. (h #g84)

### The proxy

- **proxy-mcp `tools/call` responses MUST be MCP results (`{ result: { content, isError } }`), never JSON-RPC error envelopes**, which the CLI rejects as malformed. All three error paths return `isError: true`; `requestId`/`requestMethod` are hoisted above the try, so do not regress to `id: null`. `test-proxy-mcp.ts`. (h #g78)
- **The proxy MCP endpoint is authenticated** (GHSA-3mxm-w7gf-3c5x, 0.13.2): a 256-bit bearer token in the `0600` `--mcp-config`, plus four guards **before** `readBody`: `Host` equals the bound authority, `Origin` absent, `Content-Type` is `application/json`, bearer matches under `timingSafeEqual`. Never log `authToken`. **Upgrading does not patch a running opencode.** `test-proxy-mcp.ts`. (h #g79)
- **Proxy call deadlines are per-tool, not flat.** `resolveProxyCallTimeoutMs(toolName, input, overrides)` is the single resolver for BOTH the HTTP handler and the broker, so any new timeout site must call it. Layers: 10-min default, per-tool default (`task`/`task_batch` **none**, `question` 30 min), `proxyToolTimeoutMs`, then for `bash` only `max(resolved, input.timeout)`. (h #g83)
- **A deadline of 0 means no timer, and the MCP client ceiling follows the largest deadline.** Both layers guard their timer on `deadlineMs > 0`. `resolveProxyClientCeilingMs` writes the `timeout` into Claude's `--mcp-config` (without one, Claude's HTTP MCP client gives up at 60 s) and is `MAX_PROXY_TIMEOUT_MS` whenever any tool has no deadline, because the CLI rejects `timeout: 0`. `TASK_PROXY_NOTE` must describe the real deadline (none by default; a positive `proxyToolTimeoutMs` adds one) and background mode. (h #g83)
  - **A deadline of 0 means no timer**: both sites guard `setTimeout` on `deadlineMs > 0`. Keep `buildProxyTimeoutError`'s `"timed out after"` + `"waiting for opencode to resolve"` and the `task` "do not schedule a wake-up" note. Do not reintroduce the flat `PROXY_CALL_TIMEOUT_MS`. `test-broker.ts`.
- **A proxied call ends on an event, not on a clock**: the result, an abort, the next message's orphan sweep, the child dying, a deleted session or host exit; a hung-up CLI or respawn keeps the entry for late-result recovery. **Every terminal-event test asserts both registries.** `test-proxy-task.ts`. (h #g82)
- **A call with no deadline reports itself, because nothing else will** (`PROXY_STALL_WARNING_MS`, 5 min, repeating); it **never ends a call**. Armed only at `PROXY_NO_DEADLINE_MS`, WARN, `unref`'d, removed via `clearPendingTimers(pending)` because a call holds **two** timers. `test-broker.ts`. (h #g81)
- **Proxy recovery (0.15.0)**: SSE replies flush headers at once plus keepalive comments, and JSON-only clients get the same via `openJsonStream`. Only broker-backed calls stream, and nothing flushes before the four guards ran. `pendingProxyCompletions` must be consumed once at both terminal boundaries and preserved across respawn. `test-proxy-task.ts`. (h #g119)
- Two forks measured the ~300 s proxy wall as undici's `headersTimeout`/`bodyTimeout` plus a 300 s MCP-idle timer; the 0.15.0 fix covers it. Do not claim a specific timer without fresh evidence. (h #g68)
- **Do not wait for `message_stop` to drain proxy calls**: it deadlocked two ordinary Bash calls, because the CLI blocks inside the MCP call before emitting it. Our broker drains as calls arrive. (h #g69)
- **`proxyOpencodeMcpTools` is off by default, and MCP tools are discoverable only from `doStream`'s `tools` argument**: they join the model tool set after `ToolRegistry` is enumerated, so `client.tool.list()` never sees them. **Pair it with `strictMcpConfig: true`**, or the CLI calls the server directly. `test-proxy-mcp.ts`. (h #g80)
  - `resolveMcpProxyToolDefs` does the `<server>` / `<server>_<tool>` prefix match, and `excludeServers` covers only servers a def was built for, so an unmatched server is never stranded. The bridged config file is content-addressed **over the file body, not over `hash`**.
  - **`--mcp-config <configs...>` is variadic**: push the flag once followed by every path, never a repeated flag, and parse every argument until the next option.
  - `proxyOpencodeTools` (PR #38) needs an explicit allowlist keyed on registry ids, because a plugin-declared tool belongs to no MCP server and no prefix rule reaches it.

### Tools and streaming

- `signature_delta` is expected encrypted thinking metadata. Ignore it quietly; do not treat it as an error.
- `WebSearch` with the default `"claude"` routing must NOT be forwarded as a tool-call part, because opencode has no registry entry and the AI SDK rejects unknown tool names. `mapTool` returns `skip: true` and the sites render a `> **Web search:** …` line; explicit `webSearch: "<tool>"` still forwards. `test-tool-mapping.ts`. (h #g72)
- `tool-input-delta` parts must only be forwarded when `tool-input-start` was actually emitted, or opencode creates a permanently-pending `⚙ unknown` part. Gate on `started`, but keep accumulating `inputJson` unconditionally: the skip-path text rendering depends on it. (h #g73)
- **`toolCallMap` is keyed by content-block index and MUST be deleted at `content_block_stop`**: indices restart per assistant message, so a stale entry re-emits a completed `tool-call`, opencode aborts the part, and the `task` tool reports `Subagent failed`. Do not "tidy" the delete away. `test-tool-block-index.ts`. (h #g76)
- Claude CLI emits internal tools (`Agent`, `ToolSearch`, `AskFollowupQuestion`, `TaskList`, `TaskGet`, `TaskStop`) with no opencode entry; they live in `CLAUDE_INTERNAL_TOOLS` and must be skipped, or they surface as `⚙ invalid`. `TaskOutput` is the exception (a `bash echo`).
- **Subagent dispatch must be steered at the tool *and* the prompt**, or the model calls the CLI's `TaskCreate` todo tool and narrates a dispatch that never ran: `overlayTaskProxyDescription` front-loads opencode's live agent-type list, and `SUBAGENT_DISPATCH_HINT` names `mcp__opencode_proxy__task` as the only dispatch path. `test-subagent-hint.ts`. (h #g74)
  - **Claude Code truncates long MCP tool descriptions, so position is load-bearing**: `extractAgentTypeList` keeps only the list, trims each blurb to 140 chars, and the overlay puts it **first**, under ~1.4 KB (a test asserts < 1600). A unit test cannot catch truncation, so re-run the live check if you grow it.
- **`task_batch` is the only way to run two subagents at once, because the CLI serialises MCP calls.** Its `tasks` array fans out as N `task` calls in the **same** stream finish (`taskBatchChildToolCallId`), gathered by `formatTaskBatchResults`, and is validated **before** queueing (`taskBatchInputError`). `test-proxy-task.ts`. (h #g75)
  - A partial set of child results still resolves the parent with `[missing]` in the text, because returning null sends the turn down the fresh-envelope path. Fingerprint that the fan-out is still concurrent: the child intervals overlap.
- Todo ledger translates the CLI's `TaskCreate`/`TaskUpdate` family into opencode's full-list `todowrite`. State in `src/todo-ledger.ts`, keyed by Claude CLI session id, cleared via `clearLedger`; without `sessionId` in `MapToolOptions` both fall back to `{skip: true}`. `test-todo-ledger.ts`. (h #g85)
- Subagent todos require `permission: { todowrite: "allow" }` on the subagent definition, or opencode injects `todowrite: false` and the synthetic todowrites surface as `⚙ invalid`. Built-in `general` denies it by default. (h #g86)
- **A failed CLI tool needs `isError: true` on the `tool-result` stream part**, not just error text, because opencode's bridge routes on that flag. AI SDK v3 has no `tool-error` part a provider can emit; the source is `block.is_error`. (h #g112)

### Models, effort and spawn env

- The `chat.params` hook tags opencode's active agent into provider options. Write to `output.options` at the **top level**. Do not pre-nest under `output.options[providerID]`, or the model sees `providerOptions[id][id]`. (h #g40)
- Reasoning effort is a spawn-time env var (`CLAUDE_CODE_EFFORT_LEVEL`), not message text; 2.1.x only recognises `ultrathink`. Fixed per process, so effort is part of the session key (`::effort=<level>`). Compaction spawns never carry it. (h #g41)
- **Per-agent model override (`src/agent-models.ts`) swaps the model NAME only, never the provider**: it must reattach the `@<account>` marker or work silently moves to the default account. `defaultSubagentModel` is **unset by default**, only discovered agents are eligible, an unknown id is refused, and the effective model is in the session key in BOTH entry points. (h #g42)
- **An agent's declared `reasoningEffort` beats the effort the call arrived with** (`resolveAgentEffort`), because a subagent inheriting `max` fails in the expensive direction. Declaring nothing keeps the inherited value, an unknown level is refused, compaction is exempt. (h #g43)
- `/compact` must not fall through the no-tools title stub. It is detected via `opencodeAgent === "compaction"`, runs through `doStream`, uses a fresh short-lived process, skips MCP/proxy/tool wiring, and defaults to `claude-haiku-4-5`.
- Compaction model precedence: `CLAUDE_CODE_COMPACTION_MODEL` env var, then `compactionModel` provider option, then `claude-haiku-4-5`.
- Opus 4.7 omits thinking summaries by default. Ask with `--thinking-display summarized`, but only when `src/cli-version.ts` confirms CLI >= 2.1.142. Older CLIs must skip that flag instead of crashing.
- Respect user Claude Code env vars. Do not delete or override `CLAUDE_CODE_DISABLE_THINKING`, `CLAUDE_CODE_DISABLE_ADAPTIVE_THINKING`, or explicit `CLAUDE_CODE_SHOW_THINKING_SUMMARIES` values. Same rule for the hygiene vars below.
- **Every spawned child gets `DISABLE_AUTOUPDATER=1` and `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, and the reason is the version cache, not tidiness**: `detectCliVersion` caches per `cliPath` and three flag gates read it. `cliHygieneEnv` **fills gaps only**, which is the escape hatch and why this needs **no provider option**. `test-spawn-env.ts`. (h #g48)
- Reasoning stream parts are only started after the first non-empty `thinking_delta`, so a thinking block with no text does not produce an empty Thinking row.
- opencode's own reasoning features live in its **native** runtime, which this plugin deliberately bypasses by routing through the `claude` CLI. Do not re-investigate adopting them: it would mean abandoning the CLI wrapper. (h #g50)
- Model display names carry a list-price multiplier as a `(N×)` suffix (`defineModel`, `multiplier`): haiku 1×, sonnet 3×, opus 5× (Opus 5.5: 4×, its fast mode 8×), fable 10×, mythos 10×. Display-only, and `test-config-models.ts` asserts them. (h #g51)
- **Fast mode's `-fast` model ids are OURS, not Anthropic's**: `parseModelId` strips the marker before `--model` and emits `--settings '{"fastMode":true}'`. Do not pass the id through: Anthropic's real `-fast` names are retired and there is no `--fast` flag. Only Opus 4.8 / 5 / 5.5 qualify. `test-cli-args.ts`. (h #g52)
- **Fast mode fails soft, so the downgrade must warn, not notice**: an ineligible account returns `fast_mode_state: "off"` and runs at standard speed while the picker advertises 10×. `reportFastModeState` uses `log.warn` deliberately, deduped per reason per process. (h #g53)
- Sonnet 5 is on **standard pricing** ($3/M in, $15/M out, `sonnetCost`, 3×) since 2026-09-01. The `sonnet5Cost` constant is gone; do not reintroduce it, and do not "correct" the 3× suffix back to 2×.
- **Costs in `src/models.ts` are dollars per MILLION tokens**; opencode divides by 1e6 itself, so do not "restore" the `1e-6` form. `opusCost` $5/$25, haiku $1/$5, sonnet $3/$15, fable/mythos $10/$50; Opus 5.5 (`opus55Cost` $4/$20) and its doubled `opus55FastCost` cannot share `opusCost` and need CLI 2.1.280+. `test-config-models.ts`. (h #g55)
  - Set any new model's cost from published **standard** (not Fast Mode) pricing. **Every entry carries its published `limit`**: the 4.5 generation is 200k / 64k, 4.6-and-later 1M / 128k, all pinned by the test.
- **No long-context pricing tier exists, do not add one**: 4.6 and later include the full 1M window at standard pricing, so `cost.tiers` / `cost.experimentalOver200K` stay unset. Re-open only if Anthropic publishes an above-200K rate. (h #g56)
- Billing: since 2026-06-15 Anthropic bills `claude -p` / Agent SDK usage against a separate monthly Agent SDK credit on subscription plans; API-key auth is unaffected. Fixes for a rejection are account-side. (h #g57)

- **The skill bridge (`bridgeOpencodeSkills`) stays off by default**: every bridged skill is also in the system prompt opencode forwards, so a large set is paid for twice per turn. The bundled `claude-code-plugin` skill is staged regardless. It stages a throwaway `--plugin-dir` (gated by `detectCliSupportsFlag`) on the headless, `doGenerate` and interactive spawns, never on compaction. Discovery covers every root opencode reads (`.opencode/`, `.claude/`, `.agents/` walking up, its config dirs, `~/.claude/skills`, `~/.agents/skills`), honours `OPENCODE_DISABLE_EXTERNAL_SKILLS` and `OPENCODE_DISABLE_CLAUDE_CODE_SKILLS`, and keys a skill by its frontmatter `name:`. `test-skill-bridge.ts`. (h #g65, #g66)
- **`bridgeSkipNativeSkills` is on by default and must stay on**: those roots overlap Claude's own, so `dropNativelyLoadedSkills` skips a skill Claude already loads (same realpath, identical `SKILL.md`, or the same name at user or project scope, found by `discoverNativeClaudeSkills` under the account's own `CLAUDE_CONFIG_DIR`). A same-name skill with different content is never dropped silently: Claude's copy wins and a WARN names both paths. `false` brings every duplicate back. (h #g67)

### Prompt and transcript

- **`AGENTS.md` must not reach the model twice** (`buildAppendedSystemPrompt`): opencode already forwards `~/.config/opencode/AGENTS.md`, so push the disk copy only when the forwarded `extraSystemContent` does not contain it. No match keeps the old behaviour, so the interactive transport never loses it. `test-compaction-model.ts`. (h #g58)
- **A `tool_result` may only be sent back for an id THIS CLI process issued** (`cliToolCallIds`, issue #29), because opencode runs some tools itself and the resumed session never emitted those `tool_use` blocks. Unmatched ids render as `<opencode_tool_result …>` text **before** the trailing user message. `test-get-claude-user-message.ts`. (h #g121)
  - Read `cliToolCallIds` from `getPendingProxyCalls(sk)` **before** `userMsg` is built; `doGenerate` passes an **empty** set, and omitting the option keeps the old unconditional block. Log fingerprint: `rendering opencode-side tool result as text`.
- **The fresh-session history fallback must render tool content, not count it**: `compactConversationHistory`'s `fresh-session` mode includes `tool` roles and uses `renderMessageContentForCompaction`. Do not "simplify" this back to placeholders. (h #g122)
- **Every `▌`-led text part the plugin writes must be registered in `PLUGIN_NOTE_MARKERS`** (aside, `TURN_STATS_MARKER`, self-compaction, rate limit, failed result, doctor): none was ever Claude's output. The strip is **part-level and anchored at the start**, so each note needs its **own** text part. `test-turn-stats.ts`. (h #g108)
- **Auto-continue never fires on current Claude Code CLI**, because the CLI always emits a `stop_reason` and `shouldAutoContinueIncompleteTurn` treats it as authoritative, so `"smart"` behaves as `off`. Do not delete that guard, and do not delete the keyword heuristic below it: it is the fallback for CLIs that omit `stop_reason`. `test-auto-continue.ts`. (h #g104)
  - The one exception is `isTruncationStopReason` (`max_tokens`, plus the `max_output_tokens` alias), authoritative in the other direction and bounded by the attempt and elapsed rails, because a truncated prose answer dies at the `no-activity` gate.
  - **A compaction turn must never be nudged**: `AUTO_CONTINUE_PROMPT` is the inverse of a `/compact` turn's job and the text would land in the stored summary. `autoContinueEnabledFor(compactionMode, configured)` gates it; add a compaction case to any future change here.
- **`turnStats` is off by default and must never fire on a compaction turn or a failed one** (summary corruption; the bill belongs with the error). Use the **turn totals** (`msg.usage`) so the line matches `total_cost_usd`, and pass `permission_denials` as **names and ids only**. `test-turn-stats.ts`. (h #g109)

### Questions, plan mode and compression

Both question round-trips are verified, so treat older "blocked upstream, leave it off" notes as history. The local failure was a global `notify.ts` plugin awaiting `alerter` inside `tool.execute.before`: **do not await notification delivery in a before-hook.** Do not remove the user's no-question-tool preference without their approval. (h #question-diagnosis-correction-2026-09-06)

- `AskUserQuestion` is auto-denied in `controlRequestBehaviorForTool` and rendered via `formatAskUserQuestion`. `ASK_USER_QUESTION_DENY_MESSAGE` must tell the model to **stop and wait unconditionally**, state it is **not a cancellation**, and forbid saying the question was cancelled or skipped. Do not re-add a proceed-anyway clause (issue #8). `test-ask-user-question.ts`. (h #g90)
  - The turn-local latch `AutoContinueState.sawAskUserQuestion` keeps auto-continue off for the rest of the turn, or a short trailing line looks incomplete and the nudge answers for the operator.
- **The `AskUserQuestion` fallback is dormant in headless mode**: the name is known but the tool is not offered under `--print`. Keep the machinery; do not treat "the fallback did not render" as a plugin bug without re-running the probes. (h #g91)
- Question proxy: `"Question"` is deliberately NOT in `DEFAULT_PROXY_TOOL_NAMES`, because enabling it disables Claude's `AskUserQuestion` and that swap is the operator's call. `--disallowedTools` must be computed from the **post-filter** list (`enrichedProxy`), never `resolvedProxy`. `test-cli-args.ts`. (h #g93)
  - `QUESTION_PROXY_HINT` must name the FULL `mcp__opencode_proxy__question`, or haiku calls bare `question` and opencode renders `⚙ invalid`. `fetchLiveToolInfo` does ONE `client.tool.list()` fetch for all three gates.
- **`planModeQuestion` cannot fire on the headless transport**, which does not offer `ExitPlanMode`. **`buildCliArgs` drops `--dangerously-skip-permissions` when `permissionMode` is `"plan"`**, because the CLI lets the skip flag win and plan mode was silently inert at the default. Do not "restore symmetry". `test-cli-args.ts`. (h #g94)
  - Plan mode is a capability restriction, so it wins; every other mode governs prompting and still passes both flags. `warnIfPlanModeCannotExit` warns once per process that nothing releases plan mode mid-session.
- Plan-mode approval bridge (`src/plan-mode-question.ts`) is **opt-in via `planModeQuestion`, off by default**, and **not verified**. `ExitPlanMode` ends the turn on `tool-calls` with a synthetic `question` call and the answer returns as a `tool_result` **for the original `ExitPlanMode` tool_use id**, because a "yes" in prose never unlocks plan mode. `test-exit-plan-mode-question.ts`. (h #g95)
  - `isPlanModeQuestionActive` is resolved in the **prologue**, since a reused process never reaches the spawn block. Both transports have two ExitPlanMode sites each, so change a site's twin too; `finishReason` must be `tool-calls`.
- Registry and cleanup semantics (superseding older lifetime-cache wording): `createLiveToolInfoLoader()` shares one lazy `client.tool.list()` within a `doStream` turn, and `deleteClaudeSessionId()` is the cleanup boundary for pending ExitPlanMode approvals, which respawn preserves. (h #g102)
- **opencode's `question` tool returns one sentence, not the answer**, so every unwrapper must parse it. `unwrapOpencodeQuestionResult` matches the stored question text whole, because the failover question quotes the account name and a split on quotes lands wrong. `test-account-failover.ts`. (h #g28)
  - `consumeAccountFailoverAnswer` takes a `fallback` applied to the **newest message only**, so a restart between form and answer still resolves, and `getClaudeUserMessage` strips the dialog up front. Not live-verified with a real usage limit.
- Compress proxy tool (`src/compression-store.ts` + the `compress` def) is **opt-in via `proxyTools: [..., "Compress"]`**, absent from the defaults because it throws away the model's working context, and is the only proxy tool opencode never sees. `test-compress-tool.ts`. (h #g96)
  - Five invariants: interceptor results leave through `writeToolCallResult` (a JSON-RPC error envelope would be rejected as malformed); **the summary must survive `deleteClaudeSessionId()`**, so `clearCompression` runs only from the `!hasPriorConversation` branch plus a 32-entry cap; the reset runs inside `start()` **after** `userMsg` and `includeHistoryContext` resolved, or the history is replayed instead of compressed; it is skipped when `hasMatchedPendingResults` and fires next turn instead; and `CLAUDE_CLI_COMPRESS_NOTE` replaces `CLAUDE_CLI_CONTEXT_NOTE` only when `compress` is in the **post-overlay** list. Not live-verified end to end.
- **Two different tools want the MCP name `compress`, and the precedence is deliberate.** opencode-dcp declares `compress` directly, so no prefix rule reaches it; `proxyOpencodeTools` forwards it, **empty by default**, never automatic, because a forwarded tool executes in opencode with the calling agent's permissions. `test-compress-tool.ts`. (h #g97)

- **`stripContextReminders`** is the other half, also **off by default**. (h #g97)
- **Probing any of this live needs a scratch `XDG_CONFIG_HOME`, not just `OPENCODE_CONFIG`**, because opencode **merges** the `plugin` array with the user's global config; assert `plugin ready` appears exactly **once**, give each probe its own cwd, and keep the account marker on the model id. ### Accounts and auth

- **Account failover is ON by default, and what makes that safe is that the pick is the consent** (`src/account-failover.ts`): a usage limit ends the turn on opencode's native `question` form instead of the rate-limit error, and nothing moves until an account is picked. **Not live-verified.** Seven non-optional invariants, `test-account-failover.ts`: (h #g98)
  - Seven invariants: **detection is two exact signals, never "an error"** (`isRateLimitRejected` or `ACCOUNT_LIMIT_PATTERNS`, where **`status` is the verdict and `overageStatus` is not**, and the form also requires `msg.is_error === true`); **the override is keyed on the LIMITED ACCOUNT, not the session**, and `isAccountFailoverQuestionActive` refuses child sessions; **`--resume` can never cross accounts**, so the prologue drops process and session id when `ActiveProcess.cliPath` differs, guarded on `active?.cliPath &&`; **the `@account` suffix must come off the model id** (`resolveFailoverSpawn`); **a reset time not in the future** is clamped by `setAccountOverride`; **the dialog must never be replayed** (`stripAccountFailoverParts`, `FAILOVER_MARKER`, empty messages dropped); and **`doGenerate` takes the override with no dialog of its own**. Compaction and the interactive transport are excluded entirely.
- **An account that cannot serve is read from the `error` kind on the CLI's failure reply, never from its text.** `accountBlockKind` accepts only the five account-level kinds (`authentication_failed`, `oauth_org_not_allowed`, `account_on_hold`, `verification_required`, `billing_error`), writes an `ACCOUNT_BLOCK_MARKER` note with `loginCommandFor(configDir)`, sets `resultFailure`, and opens the switch form. Not yet seen live. (h #g30)
- `ignoreAnthropicApiKey` (0.9.1, issue #9): a stray `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN` makes Claude Code use Console billing instead of the subscription. The single strip point is `claudeSpawnEnv({ ignoreAnthropicApiKey })`. Default off; `warnIfAnthropicApiKey` warns at startup regardless. `test-spawn-env.ts`. (h #g99)
- **`apiKeySource` is the field that tells you pay-as-you-go billing is happening, and `process.env` is not**, because the CLI also takes a key from its settings scopes and an `apiKeyHelper`; `API_KEY_SOURCES` treats everything except `oauth` and `none` as a key in effect. (h #g111)

### opencode compatibility

- Verified compatible with **opencode v1.18.31**. The plugin imports none of opencode's types: `src/opencode-types.ts` is a hand-written structural mirror, so drift is silent and must be audited deliberately at each minor bump. Fetch tarballs with `curl`, not `npm pack`. (h #g87)
- **`src/opencode-types.ts` is not a copy of any single upstream type, so do not "fix" it by pasting one in**: `OpenCodeModel` blends the v1 config schema with the v2 runtime `Model`, which is what opencode actually accepts from `provider.models()`. (h #g87)
- Audit findings that still hold: `chat.params` output still has `options` at the top level; `McpStatus` is still five variants, so `enabled: status === "connected"` is correct; `PluginInput` still has **no version field**; model schema additions are all optional. (h #g88)
  - opencode hooks overlapping our hand-rolled features (`tool.definition`, the two compaction hooks, `chat.headers`, `permission.ask`) were evaluated and **deliberately not adopted**: `tool.definition` cannot reach the proxy defs and has no session scope.
- **Superseded: the old "v2 plugin API is additive, do not migrate" note was reading 1.x's v2-compat API, not opencode 2.** opencode 2 is a new major of opencode itself: the two share the `opencode` command, are not installed side by side, and V1 plugin implementations do not run in V2. Plan and probes: `V2.md`. (h #g106)
- `cwd` resolution at spawn must stay lazy: `opencodeProjectDirectory` is consumed via `resolveSpawnCwd()` only as a fallback when `process.cwd()` is unusable (`/`). Do NOT bake it into `mergedOptions.cwd` at provider registration, which freezes it at plugin init and breaks workspace switching. `test-cwd-resolution.ts`. (h #g89)
  - Serve mode adds a tier between the pin and `process.cwd()`: the session's own `directory` (`resolveSpawnCwdForSession`), fetched per call, falling back to the old resolution on failure. `describeSpawnCwd` mirrors the synchronous order only.

### opencode 2 (dual support)

- **opencode 1.18 calls a dual export's `setup` too, not only `server`**, so nothing about the host major may be process-wide: the tool vocabulary rides on each model (`ClaudeCodeConfig.hostApi`, set only by the V2 `sdk` hook), and `setup` registers nothing unless `isOpencodeV2Context` sees V2's domains. Run the V1 regression probe after any entrypoint change. `test-v2-entrypoint.ts`. (h #g31)
- **The model path is the `aisdk` `sdk` hook, and `package` is only a label**: `AISDK.language` checks the `aisdk:` prefix and takes the model from `sdk.languageModel(modelID ?? id)`. The website's docs omit that domain; the shipped `.d.ts` is what is true. (h #g32)
- **A plugin's provider transform cannot see the config's provider settings**, because V2 applies the config file's provider block after plugin transforms. `planV2Providers` reads the seed from `opencodeConfigLayers` plus the plugin's own `options`; per-call settings come from the `sdk` hook's `options` and win. (h #g33)
- **V2 renamed tools and fields, and an unknown tool name is an error there.** `src/host-tools.ts` rewrites only for a V2 model: `bash` to `shell`, `task` to `subagent` (`subagent_type` to `agent`, `task_id` to `sessionID`), `filePath` to `path`, and it drops `todowrite`, `plan_enter`, `plan_exit`, `notebookedit`. `test-host-tools.ts`. (h #g34)
- **Session and agent reach the model as headers**: `session.hook("model.request")` sets `x-session-affinity` and `x-opencode-agent`, with `kind: "compaction" | "title"` mapped onto those agent names. `resolveOpencodeAgent` reads providerOptions first, so 1.x is unchanged. (h #g35)
- **V2 sends its title request with the whole tool set**, so 1.x's "no tools means title" test missed it and every new V2 session spawned a second `claude`. `isTitleRequest` also accepts the `title` agent, for V2 models only. (h #g36)
- **The live-state client is a shim** (`src/v2-client.ts`): `mcp.status`, `tool.list` and `session.get`, with anything V2 cannot answer left out so its caller takes the no-client path. The agent **registry** is still built by `buildAgentRegistry` from disk, never from `agent.list()`. `test-v2-client.ts`. (h #g37)
- **`/btw` and the doctor are real commands** sending V1's template text through `session.prompt`. `/btw` is always `delivery: "queue"`: steered into a running turn it would swallow the turn's continuation. Answering inside a running turn is not ported. (h #g38)
- **Sandbox and probe discipline**: `~/opencode-v2-sandbox/env.sh` redirects all four XDG dirs and `TMPDIR`; always `--standalone`; never `opencode service start`, which may register a login item. A configured plugin path must be a directory, so a local checkout is `<repo>/dist`. (h #g39)

### Interactive transport

Opt-in. `spawnInteractiveProcess` returns an `ActiveProcess`-shaped shim so doStream's line handler, session reuse and eviction work unchanged. `test-claude-session-wrapper.ts`. (h #g100) Invariants:

1. `decodeUserEnvelope` converts stream-json envelopes to typed plain text, dropping image/other blocks with a logged warning; never paste base64 into a TTY.
2. A turn with no terminal stop_reason MUST stay `subtype: "error_during_execution", is_error: true`, because "cleaning it up" to `end_turn` masks truncation.
3. The appended prompt reaches the TUI only via `--append-system-prompt-file`, and carries only the plugin's CLI note, AGENTS.md guidance and continuation hint, not opencode's forwarded system prompt (`interactiveSystemPrompt: false` is diagnostic-only).
4. There is no `can_use_tool` channel, so permissions are pre-allowed via `--settings` (MCP wildcards from the live bridge config, built-ins from `interactiveAllowTools`). Do NOT pass `--permission-mode bypassPermissions`, whose confirmation defaults to "No, exit".
5. The spawn must use the configured `cliPath` and the JSONL tail the same `configDir`, or opencode hangs while Claude writes transcripts elsewhere.
6. The `Bun.Terminal` gate falls back to headless silently, compaction always takes the headless path, and `turnTimeoutMs` defaults to 30 min.

### Diagnostics and CLI events

- Startup diagnostics (`src/startup-diagnostics.ts`): one `NOTICE: claude-code plugin ready` block per process from the `config` hook, carrying versions, `claudeCli`, `cwd` **with the branch that won** (`captured` is the issue-#4 fingerprint), providers, accounts, `proxyTools`, MCP servers and `anthropicApiKeyInEnv`. `test-startup-diagnostics.ts`. (h #g101)
  - Fire-and-forget and fully wrapped, so it can never break provider registration. `describeSpawnCwd` mirrors `resolveSpawnCwd`'s priority order and a test asserts they never disagree: change both together. See the block with `OPENCODE_CLAUDE_CODE_LOG_FILE=1`.
- **The four CLI stream events in `src/cli-events.ts` were read out of the CLI's own zod schemas** (`rg -a` over `~/.local/share/claude/versions/<v>`): re-run those greps before changing a parser, and keep parsing defensive, because a diagnostic that throws is worse than one that stays quiet. `test-cli-events.ts`. (h #g110)
  - Both `compact_metadata` and `compactMetadata` are parsed, because both exist in the binary. Every reporter dedupes **once per identity per process** (`_resetRateLimitReports` / `_resetSystemInitReports` are the test seams), and WARN is for anything the user must act on.
- **A `result` with a failing subtype finishes as `{unified:"error", raw:<subtype>}`**, a deliberate widening of `toFinishReason`; it used to be an unconditional `stop`, so opencode recorded `error_max_turns` as an ordinary reply. (h #g113)
- **`conversation_reset` is announced, clears index-keyed bookkeeping, and deliberately does NOT replay history.** The handler clears `toolCallMap`, `reasoningIds`, `reasoningStarted` and `textBlockIndices` and writes a `CONVERSATION_RESET_MARKER` note. Do not add a replay: every known trigger is a clear someone asked for. (h #g29)
- **`/claude-code-doctor` is answered by the plugin with no CLI inference** (`src/doctor.ts`). The command name has **no space**; it never overwrites a user-defined command of that name; nothing secret may enter the report (no `authToken`, no API key value, no system prompt, no pending call's `input`); and the loopback self-check posts **`initialize` only**. `test-doctor.ts`. (h #g114)
- **`snapshotActiveProcesses` and `snapshotPendingProxyCalls` are read-only views** for the doctor; neither touches eviction, the child's handlers, or stdin. (h #g115)

### `/btw`

- **Native `/btw`** (`src/side-question.ts`) uses `control_request.request.subtype: "side_question"`, answer at `control_response.response.response.response`; the gate is CLI >= 2.1.258, idle headless process only, and replies route through `dispatchSideQuestionResponse`. Never send the aside as a user envelope. `test-side-question.ts`. (h #g120)
- **The aside question must be stripped of opencode's `<system-reminder>` blocks** (`SYSTEM_REMINDER_BLOCK`), or a short question goes out as 1,599 characters. Strip **wherever the block sits**, not by matching a whole part or anchoring at the end. Only this parse strips reminders; normal turns keep forwarding them. (h #g120)
- **`/btw` is asked early and kept in the conversation** (`src/btw-command.ts`): find the process by opencode session id, send the `side_question` **immediately**, remember the promise, and **hold the command until `client.session.status()` reports idle**. A no-process `/btw` answers with `BTW_NO_SESSION_MESSAGE` as text, not an error. `test-btw-command.ts`. (h #g120)
  - Three traps: the remembered answer is matched by **prefix**, not equality (dcp appends `<dcp-message-id>`); busy must come from `session.status`, not the line-listener count, which is detached while opencode runs a tool; and holding the route is fine.
- **Both lookups the hook makes are racy the instant `/btw` is typed**: doStream tags the process only after the whole spawn path, and an unregistered session is **absent from the status map and reads as idle**. `waitForAsideProcess` polls while busy and `settleSessionBusy` re-reads for `BUSY_SETTLE_MS` before concluding idle. (h #g120)
  - The settle must run **concurrently** with the request, never before it, and `answer.catch(() => undefined)` goes on immediately, or a fast failure is an unhandled rejection in opencode's process. Do not remove it as dead code.
- **The answer is written into the running turn's own reply**, falling back to the toast plus a held message. `doStream` registers an `AsideSink` per conversation (unregistered in `cleanupTurn`, its unregister deleting only its own sink) and the hook throws `BtwHandledError` on success so opencode never creates the `/btw` message. (h #g120)
  - A turn is a **run of streams**, so `deliverAsideInline` retries for `INLINE_WAIT_MAX_MS` while busy before falling back, and the block is its own text part led by `INLINE_ASIDE_MARKER`. Do not match the marker mid-part.
- **The aside's left bar is a literal `▌` the plugin emits, NOT a markdown blockquote**, and the search for a green one is closed: OpenTUI takes that colour only from theme-wide syntax scopes. `INLINE_ASIDE_MARKER` must stay the leading characters after `trimStart()`; `LEGACY_INLINE_ASIDE_MARKERS` keeps old blocks strippable. (h #g120)
- **No toast ever carries the answer**: every path that produces an answer puts it in the conversation. The **two** that stay are where nothing reaches the conversation: a bare `/btw` (`SIDE_QUESTION_USAGE`) and `BTW_TURN_TOO_LONG_MESSAGE`. `showToast` needs its receiver bound. (h #g120)
- **A receipt block goes into the turn the moment the question is sent** (`formatInlineAsideAsk`), and the answer handler **awaits** that promise first, so a receipt can never land under the answer it announces. It quotes the question **in full and untruncated**. **Updating the receipt in place is not available.** (h #g120)
- **Probing this live needs a turn that is genuinely still running**: `POST /session/:id/message?async=true` **still blocks**, so background the curl; opencode's `webfetch` times out well before 30 s; and the provider ids are `claude-code-default` / `claude-code-appical`, never a bare `claude-code`. (h #g120)

## Running The Suite

- **The `test` script forces `OPENCODE_CLAUDE_CODE_LOG_FILE=0`, and that is not tidiness**: the maintainer's shell exports `=1`, so runs appended 1,732 fixture lines and fake `plugin ready` blocks to the **live** `plugin.log`, which another session read as a broken V2 install. Tests that exercise file logging set it explicitly. (h #g116)
- **Never pipe `npm test` into `grep` inside an `&&` chain.** The pipeline exits with grep's status, not the test runner's, so a red suite reads as green and the chain continues; this carried a `npm version minor` and a tag push through five failing tests and v0.21.0 published before anyone knew. Redirect and check instead: `npm test > /tmp/run.log 2>&1; echo "EXIT=$?"`, then grep the file. (h #g117)
- **The fake-CLI recovery tests in `test-proxy-task.ts` are timing-sensitive and everything they wait on derives from `START_WATCHDOG_MS`.** Under load they fail identically on master and on released tags, so run the same file at the last known-green tag before touching code. Do not raise one of the three waits on its own: the longest path lets **two** consecutive watchdog deadlines elapse. (h #g118)
