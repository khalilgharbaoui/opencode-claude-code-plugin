Three ways to reach Claude from opencode, compared in the table below. They differ in who authenticates, who gets billed, what Anthropic's terms say about it, and how much of your machine opencode still governs. Since opencode 2.2.3 there is a fourth: opencode's own [Claude Agent provider](#opencodes-built-in-claude-agent-provider), which also drives your own `claude` and has its own section below.

| | opencode's native `anthropic` provider | This plugin | Proxy / token-reuse plugins |
|---|---|---|---|
| **Authentication** | An Anthropic Platform API key, held in opencode's own auth store. | Whatever the official `claude` CLI already holds: a subscription login, an API key, Bedrock, or Vertex. The plugin never reads, stores, or replays a token of its own, and there is no subscription token here to lift. | The Claude OAuth session, used outside the official client. Meridian runs a local proxy that maps Anthropic-style HTTP onto the Claude Agent SDK and your Claude session; `opencode-claude-auth` reads the OAuth tokens out of the macOS Keychain or `~/.claude/.credentials.json` and refreshes them against Anthropic's OAuth endpoint itself. |
| **What is billed, and to whom** | Pay as you go on the Platform account that owns the key. | Whatever the CLI's own authentication bills. Headless `--print` is the Agent SDK path; an API key found anywhere the CLI looks switches the same turn onto Console pay-as-you-go instead. `apiKeySource` on the CLI's `system` init event is the field that says which, and the plugin warns once per process when a key is in effect. On a subscription, headless and interactive turns both draw from the plan's ordinary usage limits. See [which login bills what](./troubleshooting/which-login-bills-what.md). | The subscription the reused session belongs to. Meridian's own FAQ: "Usage limits follow your Max subscription, not Anthropic API billing tiers." |
| **Terms-of-service status** | The ordinary API route. Nothing unusual about it. | Uses the official client: Claude Code does the authenticating, the same as running `claude -p` yourself. You sign in to the unmodified `claude` binary with your own account, and Anthropic's [legal and compliance page](https://code.claude.com/docs/en/legal-and-compliance) says its rules do not prevent "an end user from signing in to the unmodified Claude Code binary with their own Claude subscription". Anthropic has not approved or endorsed this plugin. | Disallowed. Anthropic disallowed reusing subscription authentication for third-party Claude use in February 2026, and each project says so in its own words: Meridian's wrapper "makes no claims regarding compliance with Anthropic's Terms of Service"; `opencode-claude-auth` calls itself "a community workaround" and notes that the terms say subscription tokens "should only be used with official Anthropic clients"; `opencode-claude-plan` quotes Consumer Terms 3.7 and asks you to accept that your account "could be suspended or terminated". |
| **Model list and fast mode** | Whatever opencode's own provider registers. | 18 ids auto-registered, Haiku 4.5 through Opus 5.5 plus Fable and Mythos, each carrying a `(N×)` list-price suffix, and any other id `claude --model` accepts passes straight through. Three `-fast` Opus ids are this plugin's own markers and opt a headless session into fast mode through `--settings` (CLI 2.1.220+). See [Models](./models.md). | `opencode-claude-auth`'s README lists 14 model ids. Meridian's lists none, because model metadata comes from opencode's own `anthropic` provider. Neither README mentions fast mode. |
| **Which tools run where, under whose permissions** | All of them are opencode's, behind opencode's permission prompts and audit log. | Your choice, per tool. `Bash`, `Edit`, `Write`, `WebFetch` and `Task` are proxied by default: Claude calls an in-process MCP tool and **opencode** executes it, under its own permissions and audit log. Anything neither proxied nor named in `extraDisallowedTools` runs inside Claude Code under `--dangerously-skip-permissions`. See [Selective tool proxy](./guides/tool-proxy.md) and [Read-only mode](./configuration/permissions.md#read-only-mode). | All of them are opencode's, because the model call is an ordinary provider call. This is the one row where the third column matches the native provider and this plugin has to work for the same result. |
| **Reasoning and effort** | opencode's own reasoning controls. | Five picker variants per model, `low` through `max`, handed to the CLI as `CLAUDE_CODE_EFFORT_LEVEL` at spawn. Effort is fixed for the life of a `claude` process, so it is part of the session key, and an agent's own `reasoningEffort` beats the effort a call arrived with. Changing the effort or the model mid-conversation carries the Claude session across to the new key and resumes it instead of replaying the thread. Thinking is Anthropic's summarized digest, not raw chain-of-thought. See [Extended thinking](./guides/compaction-and-thinking.md#extended-thinking). | Meridian's SDK-features file exposes a `thinking` key. Neither README documents per-model effort variants. |
| **Context window** | Whatever the model exposes. | The window your installed Claude Code actually runs each model in, read from the CLI itself (200k on the 4.5 and 4.6 generations, 1M on later models with Claude Code 2.1.314), all at standard pricing with no above-200K tier. Claude Code may also compact or clear its own context mid-conversation, which the plugin can announce but not prevent. | Not stated in either README. |
| **Subagents** | opencode's own task tool and child sessions. | `Task` is proxied by default, so dispatch is an opencode child session under the caller's `permission.task` rule, and `task_batch` runs two or more concurrently because the CLI otherwise serialises MCP calls. Drop `Task` from `proxyTools` and Claude orchestrates internally with no opencode child-session visibility. See [OpenCode-native subagents](./guides/tool-proxy.md#opencode-native-subagents). | opencode's own, unchanged. |
| **What you lose versus the native provider** | Baseline. | A `claude` child process per conversation (an idle `--print` holds around 250 MB) under an LRU cap, so many open chats cost memory. Claude Code can compact or clear its own context behind opencode's back. Session titles are a local keyword stub, not a model-written title. Two watchdogs exist only because a child that is alive but wedged emits no event to listen for. `/compact` runs as its own short-lived spawn, on Haiku by default. On opencode 2 there is no todo panel, because 2.x has no `todowrite` tool. opencode hooks that overlap the plugin's hand-rolled features (`tool.definition`, the two compaction hooks, `chat.headers`, `permission.ask`) are deliberately not adopted, and opencode's own reasoning features are bypassed by design, because the whole point is to route through the CLI. On Windows the interactive transport refuses an npm `claude.cmd` shim; [how the CLI is started on Windows](./internals/scratch-files-and-security.md#how-the-cli-is-started-on-windows) has the detail. | Everything in the row to the left is avoided, because opencode's runtime is doing the work. What replaces it is the account risk in the terms row, plus one more moving part between opencode and Anthropic: a local HTTP proxy, or a reader of your credential store. |

Where the third column names a project, the claim is that project's own README:

- [ianjwhite99/opencode-with-claude](https://github.com/ianjwhite99/opencode-with-claude) starts [Meridian](https://github.com/rynfar/meridian) inside opencode's own lifecycle and points opencode's `anthropic` provider at it. Its disclaimer calls it an "unofficial wrapper", says the authors "make no claims regarding compliance with Anthropic's Terms of Service", and notes that no API keys are intercepted: the proxy uses the Agent SDK over your own OAuth session.
- [griffinmartin/opencode-claude-auth](https://github.com/griffinmartin/opencode-claude-auth) registers its own auth provider, reads Claude Code's OAuth credentials from the Keychain or `~/.claude/.credentials.json`, caches and refreshes them, and syncs them into opencode's `auth.json`. Its disclaimer is quoted in the table.
- [jcubic/opencode-claude-plan](https://github.com/jcubic/opencode-claude-plan) ships no plugin at all: it is a documented plan an agent can build one from, written after opencode removed its bundled Anthropic OAuth plugin on a legal request. Its legal note is the bluntest of the three.
- The first version of this plugin, written by Émilien (unixfox) and archived since April 2026, belongs in the middle column rather than the third, and deserves the credit: it is this plugin's ancestor and it already drove the `claude` CLI as a subprocess, so it left the authenticating to the CLI in the same way. What it does not have is the opencode-side mediation. Its README states that the CLI executes every tool, that permissions go through Claude Code's own allow/deny lists with "no opencode permission UI integration", that MCP servers are Claude's rather than opencode's, and that its session key is `(cwd, model)`, so two opencode instances in one directory on one model share a process and interfere. It is archived and links here.

Policy sources: Anthropic's [Agent SDK on a Claude plan](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan) page, which is authoritative and does change (read the dated note under [Billing](./billing.md) before quoting it), Anthropic's [legal and compliance page](https://code.claude.com/docs/en/legal-and-compliance) for Claude Code, and the February 2026 report that [Anthropic banned subscription authentication for third-party Claude use](https://alternativeto.net/news/2026/2/anthropic-officially-bans-using-subscription-authentication-for-third-party-claude-use).

## opencode's built-in Claude Agent provider

opencode 2.2.3 ships a provider of its own for this, **Claude Agent** (`claude-agent`), added in [anomalyco/opencode#58782](https://github.com/anomalyco/opencode/pull/58782) and merged on 2026-10-30. It starts from the same place as this plugin: it runs your own installed `claude` (Claude Code 2.1.248 or later) through Anthropic's Claude Agent SDK, you sign in with `claude` in your terminal, and opencode never reads the saved login. opencode's maintainers say they have [Anthropic's permission](https://github.com/anomalyco/opencode/pull/58782#issuecomment-6527771235) for it.

From there it makes different choices, on purpose, and its [design notes](https://github.com/anomalyco/opencode/blob/dev/specs/v2/claude-agent-provider.md) give the reason for each:

- **opencode runs every tool.** Claude Code's built-in tools are off, and Claude gets opencode's tools through an in-process MCP server. One permission system covers everything, and the history reads the same whichever model wrote it, so switching between Claude and other models in one session works.
- **Your `~/.claude` setup is deliberately not loaded**: settings files, `CLAUDE.md` files, hooks, MCP servers, skills, auto memory, and Claude Code's own auto-compaction. opencode's own versions of those apply instead, and only opencode decides when to compact.
- **One `claude` login.** No several accounts or failover between them, no fast mode and no sidebar. opencode 2's own features work with it as with any provider: its `/btw`, and a `model` named per call on its subagent tool.
- **opencode 2 only.** The `opencode-ai` package on npm, which is opencode 1.x, is at 1.19.5.

**Use the built-in** if you are on opencode 2.2.3 or later, sign in to one Claude account, and want opencode to run every tool with your Claude Code setup kept out of it. It comes with opencode and needs no plugin.

**What this plugin still adds:**

- opencode 1.x as well as 2.x, from one package. See [opencode 2](./opencode-2.md).
- Several Claude Code accounts, each its own provider, with usage warnings before a limit, an optional switch to another account when one runs out, and the conversation carried across. See [Accounts](./configuration/accounts.md).
- Your own Claude Code setup: `CLAUDE.md`, hooks, skills and MCP servers load as they do for `claude` in your terminal, and Claude's own `Read`, `Grep` and `Glob` run inside Claude Code while opencode runs `Bash`, `Edit`, `Write`, `WebFetch` and `Task`. See [Tool proxy](./guides/tool-proxy.md).
- Fast mode on the Opus models that offer it. See [Models](./models.md).
- Every model's context window and effort levels read from your installed `claude` without a single API request, kept until `claude update`, with the plugin's prices and `(N×)` labels on top. The built-in reads windows for the picker's handful of models by switching to each one, and Claude Code checks a model switch by sending that model a one-token message (measured on 2.1.314). See [Learned from the Claude CLI](./models.md#learned-from-the-claude-cli).
- A dispatch form that picks the model, effort and account for each subagent and remembers the choice for the conversation, and per-agent caps that Claude Code enforces itself (`maxTurns`, `maxBudgetUsd`). Naming a subagent's model is not the difference: opencode 2's subagent tool takes a `model` per call for any provider, the built-in included. See [Subagents](./configuration/subagents.md).
- `task_status` and `task_cancel` for background subagents. See [Background subagents](./guides/background-subagents.md).
- A `/btw` that asks the running Claude session itself, through Claude Code's own side-question request, and writes the answer into the conversation, on opencode 1.x as well. opencode 2 has a `/btw` of its own for every provider, the built-in included: a one-shot request from the session's context, shown in a dialog and not kept. See [`/btw`](./guides/btw.md#opencode-2s-own-btw).
- A sidebar with a progress line, a row per subagent and each account's usage. See [Subagents in the sidebar](./guides/subagents-sidebar.md).
- `/claude-code-doctor`, with a `bundle` form redacted for public bug reports. See [Doctor](./guides/doctor.md).

What the plugin costs in return is the table's "What you lose" row, including Claude Code's own compaction running behind opencode's back, which the built-in avoids by turning it off.
